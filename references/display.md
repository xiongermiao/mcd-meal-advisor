# 展示版式细则

主文件第一章「第 4 步产出」只写了四条铁律，本文件是版式正本：模板、手段分工、硬上限、正反例。**出方案卡与确认单之前读一遍。**

## 一、为什么版式要单独定义

内容齐不等于看得懂。人扫一屏的顺序是：**方案名 → 金额 → 达不达标 → 最后才看解释**。如果五段信息（匹配/搭配/价格/理由/指标）用同字号的段名平铺，用户必须从头读到尾才能找到钱在哪——这就是"重点不突出"的全部原因。版式的唯一任务：把用户的视线按上面这个顺序安排。

## 二、两个形态（直接套用）

### 形态 1｜无营养诉求（日常大多数情况）

```
### ① 培根蔬萃双层牛堡三件套
## ¥40.00 ✅ 正好卡预算
双层牛堡 ×1 · 中薯条 · 可乐中杯

> **推荐理由**　预算 ≤40 里唯一的三件套，主食 + 小食 + 饮料齐全；同款单点合计 49.50，套餐省 9.50。

---
### ② 双层吉士汉堡套餐　**¥39.50**
比主推便宜 0.50；主食换成双层吉士，份量小一档——想省一点或不想吃培根时选它。
```

### 形态 2｜有营养诉求（多一行指标）

```
### ① 培根蔬萃双层牛堡三件套
## ¥39.50 ✅ 全项达标
双层牛堡 ×1 · 小杯玉米杯（薯条换）· 无糖可乐（可乐换）
热量 495/600 ✅　蛋白 26/25g ✅　钠 764/1000mg ✅

> **推荐理由**　你要 ≤600 千卡、蛋白 ≥25g，两项都过。放弃「××三件套」：830 千卡，超 230。
```

指标行的三个约束：
- **独立一行**，不放进 `>`（否则和推荐理由同形，互相稀释），也不加粗（它不是焦点）。
- 位置固定在**搭配之后、推荐理由之前**——因果顺序：先看吃了什么，再看达不达标，最后看为什么选它。
- 全部达标时只给"值/目标"极简写法（`495/600 ✅`）；**任一项未达才逐项展开说明差多少**。

> 上方两例的数值仅示范版式，不是可复用报价。每次输出必须取自当次 `calculate-price` 与 `list-nutrition-foods` 的返回，禁止照抄。

## 三、手段分工（markdown 只有这几样）

| 手段 | 视觉重量 | 该承载 | 不该用于 |
|---|---|---|---|
| `###` 标题 | 大 | 方案名（主推与备选**同级**） | 段名、口号 |
| `##` 标题 | 最大 | **主推应付金额**，一条消息仅 1 个 | 备选金额、门店名、结论 |
| `**加粗**` | 中 | 备选价格、关键数字、差异量 | 整段、连续多行 |
| 表格 | 中（有边框） | 确认单核对项、多选项对比 | 五分钟内的日常方案卡（太重） |
| `>` 引用 | 弱（缩进+变灰） | **推荐理由**、提示、免责 | **备选方案**（见第五节） |
| `---` 分隔线 | 断点 | 主推与备选之间 | 每段之间都插 |
| `✅ ⚠️ ❌` | 颜色锚点 | 达标状态（一符一义） | 装饰、语气词 |

**`##` 是唯一能改变字号的杠杆**——markdown 里其他手段都只改样式不改字号。所以它必须留给金额，不能浪费在别处。

## 四、硬上限（按单条消息计，跨消息不累计）

| 项 | 上限 | 超了会怎样 |
|---|---|---|
| `##` | 1 个（用户明确要求比价时 ≤2） | 焦点分裂，等于没有焦点 |
| `###` | 3 个（主推 1 + 备选 ≤2） | 变成清单，不再是推荐 |
| `>` 引用 | 2 段，每段 ≤2 行 | 理由写成小作文，没人读 |
| 加粗 | 6 处 | 满屏粗体 = 没有粗体 |
| 状态符号 | 每个方案 1 个总状态 | 逐项堆符号，看不出整体结论 |
| `---` | 只在主推与备选之间 | 满屏横线，割裂 |

## 五、主推与备选：靠信息量降级，不靠字号

**备选三要素**（缺一不可）：
1. 与主推**同字号**的方案名（`###`）；
2. **加粗**的价格（写在标题同一行，不用 `##`）；
3. 一行「差在哪、什么时候选它」——只报名字和价格等于没给选择理由。

**为什么不能缩小**：字号一缩、塞进 `>`，用户视觉上会把它当脚注直接跳过。选项看不见，等于没提供选项。层级差由"有没有展开明细、有没有 `##` 金额、有没有推荐理由"来体现，不由字号。

**反例（错误）**：
```
> 备选：麦香鱼 + 牛奶 ¥34.00
```
问题：缩进 + 变灰 + 小字号三重降级，且没写差在哪。

**正例**：
```
### ② 双层吉士汉堡套餐　**¥39.50**
比主推便宜 0.50；主食换成双层吉士，份量小一档——想省一点或不想吃培根时选它。
```

## 六、确认单（第 7 步）的版式

确认单是**核对版**，不是决策版，所以用表格而不是卡片流，但仍要两个锚点：

```
### 培根蔬萃双层牛堡三件套
## 应付 ¥39.50

| 项 | 内容 |
|---|---|
| 门店 | … |
| 餐品 | … |
| 费用 | … |
```

- 锚点只有两行（方案名 + 应付总价），其余全部进表格；
- **不重复推荐理由**——第 4 步说过了，确认单只在方案有变更时写一句"改了什么、理由怎么变"；
- 确认单和方案卡在不同消息里，各自可以有 1 个 `##`，不算违反铁律。

## 七、常见失败对照

| 失败形态 | 症状 | 改法 |
|---|---|---|
| 五段 `【】` 平铺 | 五个标签同重量，找不到钱 | 换形态 1/2 的标记层级 |
| 金额藏在段尾 | 用户要读三行才看到价格 | 金额提到第 2 行，用 `##` |
| 开场先复述场景 | 前 5 行都在讲"你在重庆、现在 21 点、这家店营业中" | 前两行必须是方案名与金额，场景信息压到卡后或掐掉 |
| 备选进 `>` | 备选像脚注，用户直接跳过 | 同字号 `###` + 加粗价 + 一行差异 |
| 指标逐项展开 | 三个指标各带括号解释，冲淡焦点 | 达标时用 `495/600 ✅` 极简式 |
| 每条消息两个 `##` | 主推和备选都放大，谁都不是重点 | 备选价格用 `**` 不用 `##` |
| 满屏 emoji | 🍔💰🎉 抢走状态符的颜色语义 | 只留 ✅⚠️❌，一符一义 |

## 八、和主文件其他约束的关系

- 版式只管"怎么排"，**不改变"写什么"**：五段字段的必写/禁写仍以主文件第一章的表格为准。
- 报价三态（已核价／待核价／待核实）与级联失效不受版式影响；价格一变，整卡按形态重排，不局部改数字。
- 营养台账为空时，形态 2 的指标行整行不出现，不是写"暂无"。

## 九、门店与距离的措辞（仅到店型）

**配送型整节不适用**：外送不展示门店地址、不展示距离（接口也不返回），只展示**配送地址**。规则见 `delivery.md` 第二节。

`distance` 来自 query-nearby-stores，单位米。**但它不是"离用户多远"**：接口返回的 longitude/latitude 常为 0，距离基准是本次搜索的中心点（city + keyword），不保证是用户实时定位。

**基准在展示门店列表时就要确定，不能等到最终确认单才想起**。三档：

| 定位来源 | 标准表述 | 禁止 |
|---|---|---|
| 用户给了实时定位或明确位置 | "离你约 X 米" | —— |
| 只给了店名 / 商圈关键词 | **"距该商圈约 70 米"或"按搜索位置估算约 70 米"** | "离你" |
| 无定位，拿收藏 / 最近点单作**候选** | 报店名 + 地址，注明"你收藏的店""你最近一单的店"，**不显示距离** | "离你"、展示 distance、把候选说成已定 |

- 无定位时统一用「按搜索位置估算」这几个字，不要省略成「约 70 米」——省掉限定词，读起来就变成个人距离了。
- **无定位时宁可给地址也不给距离**：`distance` 在收藏查询里常常是 0（经纬度为 0,0），显示出来等于编了一个"很近"。给完整地址，用户自己知道远近。
- **带来源的措辞不能省**："你收藏的店"和"你最近一单的店"是两种强度完全不同的依据，合并成"你的常用门店"会让用户误判。候选就是候选，措辞上也要站得住。
- **收藏门店可能不在用户当前城市**（收藏是账号级、跨城通用）。用户给的城市/商圈与收藏门店所在地明显不符时，直接用 `searchType=2` + city + keyword 重搜；收藏店最多并列提一句"你还收藏了 X 店"，**不得当默认、不得当唯一候选**，更不得因为"有收藏"就跳过位置确认。
- 距离只用于在多家**到店型**门店间排序选近，不据此承诺步行或到达时间；配送型不得据此说"这家离你近"。

> 回归断言：用户只给门店名或商圈、全程未给定位，正确行为是所有出现距离的地方都带"按搜索位置估算"或"距该商圈"——**任何一处出现"离你"即为不合格**。

> 回归断言：用户什么都没给（无城市、无定位、不提店名），正确行为是先问"在哪家店取、堂食还是带走"，**不得调用 query-nearby-stores 靠 searchType 默认值捞一家收藏门店顶上**；即使用了收藏/最近点单作候选，也必须标来源、报地址、且等用户确认后才继续。**本条仅约束到店型**——用户说的是"叫个外卖/麦乐送"时，正确动作是查地址簿并确认配送地址，不是问哪家店。
